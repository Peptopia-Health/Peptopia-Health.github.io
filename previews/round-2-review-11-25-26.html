Plants 4 — Every page at the same size

Browsing page to page, the whole site changes width — each guide family was built to its own column. The audit covered 98 pages: only 13 present at the standard size set by the two leading pages (the Artifacts and Plants indexes: a 1200px column). Proposed: one default page size everywhere, written into the build script as an early, permanent rule — with any exception named and approved in the script itself.

CURRENT — EVERY FAMILY ITS OWN WIDTH
Plant guides — 880px (13 pages)
Strain guides — 960px (12 pages)
Article guides — 900px under a 1200px header (10)
Portal family — 860px (8 pages)
MedPass one-pager — zoomed to 66%
…plus 620–1500px scattered across 40+ more pages

85 of 98 pages off-standard. Nothing is broken inside any one page — the size itself jumps as you move. One page (the MedPass one-pager) literally shrinks itself to 66%.

PROPOSED — ONE DEFAULT SIZE
EVERY PAGE — 1200px column
header clamped to the same column · no zoom, no rescaling
Plant guides · strain guides · articles · portal · artifacts — same frame, their own layouts inside it
Exceptions only as named, approved entries in the build script

The rule goes in as an early step of the Guide Build Script (§7.0) and a charter line in the Global Design System, and the width checker learns to fail any page that isn't 1200. After the change, the print/PDF check gets re-run — that's the follow-on you flagged.
